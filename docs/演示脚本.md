# 演示脚本（3 分钟）

> 目标：让面试官在 3 分钟内看懂「这是什么、解决了什么、技术上有什么取舍」。
> 不追求功能全，只追求**主线清晰**。

---

## 演示前 10 分钟检查

```powershell
# 1. 起后端（会自动编译）
pwsh -File .\scripts\dev.ps1

# 2. 起前端
cd web; npm run dev

# 3. 确认就绪
curl.exe -s http://127.0.0.1:8000/readyz     # {"status":"ready"}
```

检查清单：

- [ ] 三个服务都在跑（8000 / 8001 / 8002）
- [ ] `.env` 里的 Key 有效（打开一条差异，能出归因）
- [ ] 浏览器开好 `http://localhost:5173`，缩放调到 100%
- [ ] 关闭无关窗口、通知、微信
- [ ] `testdata/channel.csv` 和 `system.csv` 放在桌面或能快速找到

## 时间轴

### 0:00–0:20 背景（20 秒）

> 「这是一个对账系统。学校通过微信收学费，渠道第二天给一份对账单，财务要跟系统订单逐笔核对。
> 现在的问题是：2000 行 Excel 要手工比 2 个多小时，找出差异后还得靠经验猜原因。
> 我做的是把这件事自动化：上传两个文件，10 秒出差异，AI 告诉我每条为什么、该怎么办。」

**屏幕上**：停留在上传页，不要动。

---

### 0:20–0:50 上传（30 秒）

**操作**：选两个文件 → 点「开始对账」。

> 「渠道账单金额是元，系统订单是分，系统会自动归一化。
> 这里 1,960 条记录，从解析、匹配到落库，210 毫秒。」

**屏幕上**：出现「1,960 条记录 / 60 条差异」。

> 「60 条差异，不是 1,960 条——90% 以上的账其实是对的，工具的价值是把需要人看的那部分挑出来。」

---

### 0:50–1:50 差异列表 + AI 归因（60 秒）

**操作**：点「查看差异」→ 点第一行。

> 「差异分三类：渠道有系统无、系统有渠道无、金额不一致。
> 点开一条，后端会做两件事：先查库，没归因过就调模型，再把结论写回去。」

**等待 1~2 秒**（正好用来讲）：

> 「这一步大概 1 秒，因为真的在调大模型。」

**结果出来后**：

> 「它给出分类、置信度、一句人话理由，还有 evidence——就是它依据了哪几个字段。
> 这个很重要：财务能核对，审计能追溯，不是黑箱。」

**操作**：关掉，再点同一行。

> 「第二次点开是毫秒级，因为结果已经写回数据库了。
> 2000 行的任务实际只调几次模型，成本可控。」

---

### 1:50–2:20 确认与汇总（30 秒）

**操作**：点「确认无误」→ 关掉抽屉 → 看顶部采纳率。

> 「确认后状态变成已确认，顶部的 AI 采纳率会更新。
> 如果 AI 判错了，可以选正确分类做纠正，纠正记录会存到反馈表，作为后续评测的样本。」

---

### 2:20–2:45 架构与取舍（25 秒）

**操作**：切到 README 的架构图（或直接口述）。

> 「架构上是三个服务：BFF 负责对外协议和聚合，core 负责对账计算和事务，AI 独立成一个服务。
> 关键设计是——core 不依赖 AI。所以模型挂了，对账、列表、确认全都照常能用，只是没有归因。」

**可选**：如果面试官感兴趣，现场演示降级（停掉 ai 服务再点一条差异）。

---

### 2:45–3:00 收尾（15 秒）

> 「整个项目从需求、设计、编码、测试到部署都是我一个人做的，文档在 docs 目录。
> 有什么想深入看的，我可以现在展开。」

---

## 只剩 1 分钟的极简版

1. 上传（10 秒）→ 说"1960 条，210 毫秒"
2. 点第一条差异（等 1 秒）→ 说"分类 + 理由 + 依据字段，金额不由模型算"
3. 说架构一句话："三服务，core 不依赖 AI，所以模型挂了不影响对账"

## 高频追问与答案

| 追问 | 回答要点（一句话） |
|---|---|
| 为什么拆三个服务？ | BFF 管协议和聚合，core 管计算，AI 管判断；**core 不依赖 AI**，所以模型挂了主流程不受影响 |
| AI 算错钱怎么办？ | 金额全是代码算的，模型只做分类和措辞；它连数字都不能复述 |
| 怎么防幻觉？ | evidence 白名单：只能引用输入里存在的字段，编造一次置信度打八折 |
| 模型挂了怎么办？ | 规则兜底，标记 fallback=true；已实测停掉 AI 后上传/确认/汇总全部可用 |
| 成本怎么控制？ | 懒归因（点开才调）+ 结果回写 + 相同输入缓存 |
| 准确率多少？ | 自建 30 条样本上规则 50%、prompt v2 100%；但样本是自己构造的，存在过拟合，真实预期 75~85% |
| 为什么用 MySQL 不是 PG？ | 现有环境就是 MySQL，且团队技术栈一致；失去 JSONB/RETURNING，但本项目用不到 |
| 最难的地方？ | 匹配的边界：模糊匹配要求唯一候选，宁可判差异也不猜——错配会把真实差异吞掉 |
| 如果重做会改什么？ | 评测集应该从真实历史差异抽样、留 hold-out；分类阈值应该由财务确认而不是我拟合 |

## 演示失败预案

| 现象 | 处理 |
|---|---|
| 页面报 500 | 后端没起，切终端跑 `scripts/dev.ps1`（30 秒） |
| AI 一直转圈 | 说"模型调用超时，会走规则兜底"，等它返回 fallback 结果 |
| 网络卡 | 直接讲代码结构，不让演示卡住节奏 |
| 忘了要用哪个文件 | 用 `testdata/` 下那两个，文件名是 channel.csv / system.csv |
